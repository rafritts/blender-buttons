## B8 — `modifier op=move` raises NameError `_BIND_TYPES`

Both `before=` and `index=` forms fail with `name '_BIND_TYPES' is not defined`
(blind donut run, 2026-07-11 — hit reordering Solidify before Subsurf on the icing;
workaround was remove + re-add the subsurf). Undefined symbol in the extension's
modifier move handler — likely a casualty of the SPEC-22 Phase 2 deletions or an
import that never existed. Fix the reference, add a headless e2e that actually
reorders a stack both ways.

## B9 — `edit op=randomize` is not native Randomize: axis-restricted jitter, Z default

Native Mesh ▸ Transform ▸ Randomize (`transform.vertex_random`) displaces verts in
3D (amount/uniform/normal-weight/seed — no axis concept). The shipped op kept the
old jitter machinery: a single `axis=` displacement defaulting to Z (blind donut
run, 2026-07-11 — dough came out wavy only vertically; the outline stayed perfectly
round and the agent noticed the mismatch against its Blender instincts). SPEC-22
§5.1 (native name ⇒ native semantics and defaults) says this should wrap or
faithfully reproduce `transform.vertex_random`; an axis *restriction* is not a
native parameter.

## B10 — `object op=group` double-links: object stays in its previous collection

Grouping links objects into the new collection without unlinking from the old one,
so they appear in both (blind donut run, 2026-07-11 — sprinkle prototypes ended up
in `SprinkleProto` *and* the scene default). Native Move to Collection (M) moves.
Either unlink-on-group to match the native verb, or rename the semantics honestly
(link_to_group) — SPEC-22 favors the former.
